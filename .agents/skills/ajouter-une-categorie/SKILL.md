## Goal
Add a content category while preserving existing behavior.

## Rules
- Inspect the current architecture before making changes.
- Reuse existing patterns where appropriate.
- Do not assume that storage or navigation works
  differently from what the code demonstrates.

## Workflow
1. Inspect the existing category implementation.
2. Identify the files affected by the new category.
3. Confirm the category's name and required behavior.
4. Implement the changes using existing conventions.
5. Check storage and navigation behavior.
6. Run relevant tests or checks.
7. Report the modifications and any remaining issues.

## Examples
Follow the existing category implementation
when introducing a new category.
